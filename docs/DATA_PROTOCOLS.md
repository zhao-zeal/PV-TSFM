功率沿用数据文件值，不另做StandardScaler或无容量证据的MW/nMAE换算。15维NWP按训练站点网格和训练时段拟合StandardScaler，卫星按训练时间内共享图像拟合scaler；跨站测试复用源训练参数。NWP按网格时间排序并双向插值。CSV缺少发布时间，未来NWP按约定假定在预测起点可用，尚未验证严格在线无泄漏。

协议逻辑在 `data_provider/protocols.py`、`mmsp_storage.py`、`split_utils.py`；每次真实运行在checkpoint/输出目录保存data_protocol.json与scalers.npz，无需保留一次性协议验收副本。

## 模型输入

统一数据接口保证站点与窗口对齐，模型可使用不同模态。加载范围不等于模型实际消费的信息。

| 模型/版本 | 实际输入 |
| --- | --- |
| DLinear / PatchTST official | 历史功率 |
| DLinear / PatchTST legacy_fusionsf | 历史功率+经纬度，旧三通道版本 |
| FusionSF三模态guide17 | 历史功率、历史卫星、未来15维NWP；guide额外添加经纬度，保留坐标/时间编码 |
| FusionSF当前2模态入口 | 功率+卫星；不能替代历史功率+NWP对照 |
| Cross-Unet | 历史功率、历史/未来NWP及相关历史块 |
| TimeXer | 历史功率+历史NWP，当前forward不使用未来NWP |
| Chronos-2 | none/history/future/history_future四种NWP模式分别登记；当前NWP先做训练集标准化 |
| ChronosX | 功率、历史/未来NWP及作者缺失标记/注入处理；不等于Chronos-2 |
| Time-VLM | 历史功率衍生图像和文本，不等于MMSP卫星观测 |

相同协议下比较时注明模型版本、实际输入及变换；输入信息更多不能单独证明架构更优。guide15与guide17、原始NWP与标准化NWP分别记录；forecast-only分支不意味着骨干没有天气输入。

## 评价与历史边界

正式测试覆盖全部站点、全部24步和夜间样本，不额外裁剪负预测，不施加mask。MAE/RMSE按全部预测元素计算；R²用全局目标均值，不平均站点R²，代码见 `utils/metrics.py`。测试不参与选模；每模型记录验证选模依据，当前FusionSF用验证MAE。

当前正式十站点协议为上述两个，`site1_v1`用于单站点探索，保留旧中止实验记录。2026-10-10重新核对站点、全部目标窗口归属、首/中/末样本张量与天气时间对齐，独立重算Site #1训练网格NWP scaler均通过；未发现需要修改的协议实现。检查证据更新于`reports/site1_FusionSF_lr0p00016_20261010/summary.json`的`protocol_recheck`，没有进行模型训练或正式评估。`paper_main_v1`使用分区内完整历史/目标窗口和全量scaler，历史测试25,210窗口；它不等于当前in_domain的25,450窗口。旧legacy测试25,580窗口以及验证站点#20–#21等缓存协议也不混表。

`fixed_v1`是历史窗口/预处理名称：BasicTS部分站内实验使用该旧名，FusionSF B/C/D/E主要使用跨站划分。底层兼容别名不能代替站点、时间索引、scaler与输入核对。正式记录明确写in_domain或zeroshot_v1并保存实际协议，不与论文旧表直接排名。

历史探索保留在独立FusionSF项目。协议、输入、模型版本与评价全部一致且证据齐全，才可在统一入口复评并申请复用；不一致则重新运行，可训练模型涉及训练输入/协议改变时重新训练，冻结模型重新推理，旧表征缓存相应重建。缺证据标为待核对，不猜测通过；重跑逐项审批。
